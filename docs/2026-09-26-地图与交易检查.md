# 校园地图与买卖流程更新

## 本次实际修改

- 地图改用 Leaflet 1.9.4，搜索后平滑移动并高亮对应地标，支持“一教／教一／2号楼”等别名。已标注9处可核实的公共地标；不猜测未核实地点的位置。
- 使用学校公开全景里的1800×732校园沙盘底图，保留独立的站内全景视图。定位导览是立体效果的静态底图，不是可自由旋转的三维建筑模型，也不提供实时路线导航。校园实景照片继续保留原有高清资源。
- 删除原来的43项“能搜索名称但无法切换场景”的列表，避免假定位。图中地点可复制到聊天中约定面交；搜索无结果会明确提示。
- 下单前确认卖家、交付方式、商品价格、运费及合计。面交不收运费；支持两种交付方式的商品由买家明确选择，并保存订单快照，后续不随商品修改而变化。
- 服务端校验商品价、运费和退款金额，拒绝负数、异常精度以及不能正确结算的部分退款。现有普通退款流程仅支持全额退款。
- 余额以数据库原子加减更新；订单、商品、跑腿和争议处理增加必要行锁及状态检查，防止并发付款、重复结算、旧状态覆盖以及收藏操作误改商品状态。
- 退款中暂停交付、验收与自动确认。退款卡显示申请原因、金额及时间；未交付申请展示自动退款期限，已交付退款不再超时自动全退或重新上架。
- 未交付的退款遭拒后可以申诉；争议被驳回仍保持待交付与资金托管，不能提前付给卖家。
- 短信未配置时明确报错，不再假报发送成功。补齐 Docker 构建依赖、HTTPS/API/WebSocket 反代样例及统一 CORS 来源配置，详见《上线部署.md》。

## 还值得做什么

| 优先级 | 建议 | 原因与范围 |
| --- | --- | --- |
| 上线前 | 完成真实支付、退款、提现的闭环，或明确选择仅线下面交结算的产品模式 | 当前只有站内余额，暂未接入在线充值或支付机构；不能把余额流程当作真实支付已完成 |
| 上线前 | 配置图片存储与账号验证服务 | COS未配置时无法上传新商品图片；短信注册和找回密码需要可用服务 |
| 高 | 面交预约与一次性核销码 | 将地点、时间和买家确认收货串起来，避免卖家单方面标记交付后引发争议 |
| 高 | 待付款订单有效期与自动关闭 | 避免长期待付款订单影响商品编辑、管理；需要同时处理重复下单和商品恢复状态 |
| 中 | 求购区、收藏降价提醒 | 有明确校园场景，先做小范围功能再观察使用情况；提醒必须支持取消订阅 |

已有商品评价、收藏、聊天、举报与交易争议，应保留并完善。暂不增加购物车、复杂优惠券、会员积分、抽奖、直播等与单件校园闲置交易关联较弱的功能。之前已删除的AI估价、校园AI助手、黑暗模式和无效设置不恢复。
